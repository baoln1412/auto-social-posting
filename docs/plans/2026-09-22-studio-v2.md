## 1. What the owner said, and what the code shows

**A. "The approach for getting the post is not correct."** Three entries exist today and none is
the pipeline: the `/studio` box (`NewRunBox.tsx`) stores the text raw as `item_ref`, and
`steps/fetch.ts:cfgFor` uses it as a URL only when the channel's source `needs === 'url'` — on a
gold channel a pasted link is silently ignored and the first listed item is used; the gold
suggestions; and the channel wizard, which is one source per channel with no feed list, no filter,
no output shape. The crawler's real configuration lives in the old SPA (`Settings → SourceManager`)
and Studio cannot see it. So there is no place to say *what* to fetch, *how* to filter and order it,
and *what the post should look like* — the thing the pipeline is for.

**B. "Too few options to edit the output."** `OverrideDrawer` has four selects, three checkboxes
and a text field. `KitEditor` is schema-driven with **labels = schema keys**. ThreadViral's
configurator has eight tabs and ~40 controls (§4), a per-run drawer with 12, and a layer editor.
v1 marked half of them `engine` or `later` and made the layer editor conditional; the owner
overruled that: copy ThreadViral, combine with ours.

**C. "Each step should be viewable when I change the options, not at the last step only."**
`previewStep` runs server-side once per page load for the current step; changing a drawer option
or ticking a comment updates client state only; the preview refreshes after the next
`POST advance`. That is the opposite of the reference, where the phone frame in the middle of
`Cấu hình video` redraws on every control.

**And one misreading that shaped the New page.** The four chips `Đọc bài · Viết lời đọc · Lồng
tiếng · Video dọc` on ThreadViral's New page (`ref/tv-24`) are the **pipeline's step rail** — what
will happen to the link — not four kinds of video. v1 turned them into `mode` and the executor
built "Chọn kiểu video". v2 removes the modes; the rail lives on the run page, one screen per step.

## 2. The shape: two doors, one rail

```
/studio
┌──────────────────────────────────┐ ┌──────────────────────────────────┐
│ NGUỒN TỰ ĐỘNG                    │ │ MỘT BÀI                          │
│ crawl + pasted sources → filter  │ │ paste a link or text → post →    │
│ & order → output shape → preview │ │ card → reel, for this item only  │
│ on 3 items → schedule → GOLD     │ │                                  │
│ [Thiết lập]  [Chạy ngay]         │ │ [ link / text ] [Kênh ▾] [Tạo]   │
└──────────────────────────────────┘ └──────────────────────────────────┘
Gợi ý từ kho nguồn (Gold rows with no reel)        Kết quả gần đây
```

Door 1 is the pipeline the repo already has (`/api/pipeline/*`, `SourceManager`, market context,
system prompt), given the step-by-step setup ThreadViral gives a single video. Door 2 is v1's run,
with the URL honoured on every channel and the source type detected from the link.

Both doors end on the same **run page**, whose rail is `Đọc bài → Viết bài → Ảnh → Video → Đăng`.
Each step is its own screen: options on the right, the preview in the centre, cost and `Tiếp`
at the bottom. The pipeline's setup uses the same screen component with its own five steps.

## 3. The preview contract — the C fix, one mechanism everywhere

`lib/studio/steps/types.ts` gains:

```ts
export interface StepOptions { [key: string]: unknown }      // this step's controls, from the kit + drawer + this screen
preview(input: I, ctx: RunCtx, opts: StepOptions): Promise<StepPreview>   // pure of side effects, cost 0 or stated
```

- `POST /api/studio/runs/[id]/preview { step, opts }` runs `preview` with the current options and
  returns `{kind, data, cost, stale:false}`. The client calls it **debounced 400 ms on every
  control change**; while a call is in flight the frame shows the last result with a `stale` veil.
  `advance` still books the cost from its own `preview` call — the two never disagree because it
  is one function.
- Cheap by construction: `draft` preview is text (the rewrite is cached by `hash(item, opts)`;
  a changed option that does not touch the prompt re-uses it); `image` preview is the card PNG
  (fast, cached by param hash under `public/studio-runs/`); `reel` preview is the **scene list +
  the current scene's composed frame** (card + background + caption preset + sticker + signature,
  drawn by `steps/overlay.ts` on one frame, no ffmpeg run of the whole reel); `voice` preview is
  one sentence through edge-tts, cached by `(voice, rate, pause, text)`.
- The kit editor's centre canvas is the same `image`/`reel` preview with a sample item, so a kit
  change is seen on a real frame, not on a schema form.
- `Duyệt trước khi dựng` (`auto_continue` off) is what makes every step wait; on, the run walks
  the rail and only `Video` costs anything.

**Test that proves C:** Playwright — change the caption preset on the Video step; assert the frame
image's `src` hash changes within 2 s without clicking `Tiếp`.

## 5. Door 1 — Nguồn tự động, five steps, writes Gold

`/studio/pipeline/[market]` — a setup per market, using the run-page screen component with its
own rail. Stored in `studio_pipelines (market_id, config_json, revision, updated_at)`; the
existing `/api/feeds`, market context and system prompt are **read and written through it** so the
old SPA and Studio see one configuration (no second source of truth).

1. **Nguồn.** The crawled feeds of this market (from `/api/feeds`) with on/off and weight, plus
   `+ Thêm nguồn`: paste anything — RSS, a site (discovery via `SourceManager`'s existing
   discovery call), a subreddit, a Threads account, a Facebook page, an Instagram account. Each
   pasted source runs the **fetch test** (3 real items or the error) before it can be saved.
   Facebook and Instagram fetch through the Graph API with the token in env; absent, the source is
   listed as `cần token` with the setup link, not hidden. `KeywordFilterConfig.tsx`, `ChannelManager.tsx`
   and `FacebookConnect.tsx` exist unreferenced — reuse their parts, do not resurrect keyword gating.
2. **Lọc & xếp.** Hard filters only where the pipeline already has them: market, language, dedupe,
   the compliance rule. Everything else is **ordering**: topic keywords as boosts, source weight,
   recency, comment count. Never a keyword gate and never a relevance floor — both were measured
   NO-GO (memory: 35–58 % of applied sources dropped). The preview here is the ordered queue of
   the last crawl with the score breakdown per row.
3. **Đầu ra.** The post shape for this market: format preset (Tin ngắn · Giải thích · Danh sách ·
   Hỏi-đáp · Câu chuyện — each a prompt fragment in `lib/studio/formats.ts`), length band, tone,
   language, title style, hashtags (from the kit), CTA line, citation style ("Theo <source>"
   always), the Meta compliance rule (always on, shown, not toggleable). Preview: the three items
   from step 2 drafted **now** with these settings, side by side, each with its compliance chip.
   The prompt fragment is editable in a drawer; re-preview is free (cached per hash).
4. **Ảnh & video mặc định.** Which kit this market uses for cards and reels; whether the pipeline
   also renders a card per post (today: yes), a reel per post (today: no — reels are made on
   demand from Gold). Preview: one item through card and the reel scene list.
5. **Lịch.** Run now (calls `/api/pipeline/run` for this market) · schedule (the existing
   scheduled task, shown, editable) · **writes Gold**. Done shows the pipeline status bar and the
   new Gold rows, each with `Mở trong Studio`.

Every step's `Tiếp` is disabled while `checked === 0` or findings exist — a source that fetches
nothing cannot be saved, an output shape whose three previews fail compliance cannot be scheduled.

## 6. Door 2 — Một bài

`NewRunBox` becomes: one box (`Dán link Threads / Reddit / Facebook / Instagram / bài báo, hoặc
viết nội dung…`), the channel select, the gear. **The URL is honoured on every channel:**
`lib/studio/sources/detect.ts` maps the link to a source type (`threads.net` → threads,
`reddit.com` → reddit, `facebook.com` → facebook, `instagram.com` → instagram, anything else →
article; no link → text) and the run's fetch step uses that source with the channel's kit. The
fetch preview shows the item and its comment pool before anything is spent.

## 9. Traps this repo already paid for (v1 §9 still applies; these are new)

- **Preview must be cheap or it will be skipped.** A preview that runs ffmpeg on the whole reel
  will be debounced into uselessness; the reel preview is one composed frame.
- **Schema keys are not labels.** `KitEditor` shipped with `card.engine` as a label. Every
  control has a Vietnamese label in `labels.ts`; a test fails on any control without one.
- **Ordering, never gating.** Keyword pre-filter and relevance floor are measured NO-GO; if a
  reviewer proposes a hard filter, the answer is the measurement, not a toggle.
- **The two configurations must be one.** Studio's pipeline setup writes the same feeds, context
  and prompt the old SPA reads; a second copy drifts on the first edit.
- **`item_ref` was raw text.** Detect the source from the link; never fall back silently to "the
  first listed item" — that is the bug behind complaint A.
- **A screenshot pair is the acceptance test for UX parity.** The reference is in `docs/plans/ref/`;
  put ours beside it. "Looks fine to me" does not close a slice.
- `rtk proxy curl` for pipeline fetches; DuckDB single writer; committing ≠ deploying
  (`.next/BUILD_ID`); `/studio` 404s without `STUDIO_ENABLED=1`; Playwright cannot open `file:` —
  serve.
