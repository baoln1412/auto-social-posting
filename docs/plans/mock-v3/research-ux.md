# ThreadViral → Desoul light rebuild: pattern research

Sources: local screenshots `docs/plans/ref/tv-{21,23,24,25,28,33,12,32}-*.jpg`, `desoul-brand` SKILL.md + brand.json. Web evidence linked inline.

## A. Why it read as "plain text" — causes + fixes

1. **Mono used for labels/headings, not just numbers.** Brand rule is "every number is mono," not every string. Fix: Baloo 2 for headings, Source Sans 3 for labels/body, Source Code Pro reserved for credit counts, %, px, durations, ids only.
2. **ALL-CAPS used for hierarchy instead of size/weight.** Gumroad and the NN/g neobrutalism writeup build hierarchy with size and weight contrast, not case — caps are reserved for tiny eyebrow labels (section dividers like "BẮT THÊM CHO VIDEO NÀY" in tv-24), never headings or body. [nngroup.com/articles/neobrutalism](https://www.nngroup.com/articles/neobrutalism/)
3. **No icons.** Every reference nav row, section header and empty state in ThreadViral carries an icon; light creative tools do the same (Canva's editor sidebar is icon-led at 320px, collapses to 56px icon-only). Fix: Lucide icon on every sidebar row, every settings-section header, every empty-state panel. [shadcn.io/design/canva](https://www.shadcn.io/design/canva)
4. **No filled CTA.** Desoul's one-accent rule is a strength but only if the accent is actually applied as a *solid fill* on the primary action, the way Gumroad reserves black as "the only filled button color." A link-colored or outlined-only "primary" button reads as inert. [duply.ai/gumroad/design-md](https://duply.ai/gumroad/design-md)
5. **Empty tiles with no icon/copy/CTA.** NN/g and SaaS-empty-state research agree: a blank rectangle reads as broken, not empty. ThreadViral's own tv-21 (locked ảnh nền tab) is the model to copy exactly — lock icon, benefit headline, helper line, filled CTA. [nngroup.com/articles/empty-state-interface-design](https://www.nngroup.com/articles/empty-state-interface-design/)
6. **Black box for the video preview.** The dark surface is *correct* — every light creative tool nests a dark canvas inside a light shell (Canva, Figma, Descript, CapCut). The bug isn't the color, it's the content: the box needs a rendered phone frame + mock overlay (as tv-25 shows), not emptiness, and it needs a pen-outlined bezel card so it reads as a deliberate inset, not a rendering failure.
7. **Raw label+select forms.** No icon-led rows, no grouping, no radio/toggle cards. Fix: the settings-panel density pattern below (icon + title + helper caption + control) and the radio-card pattern for exclusive choices.
8. **Pen+shadow applied to nothing or everything uniformly.** Depth reads only when outline+hard-shadow marks *specific* raised/interactive surfaces (cards, buttons, chips) and is deliberately absent elsewhere (chrome, canvas, plain text). Neubrutalist systems that work (Gumroad) are disciplined about exactly which surfaces get the treatment.

## B. Pattern sheet — 8 reference screens → Desoul/light version

**1. App shell (tv-21 sidebar+header).** Keep: icon+label nav column, one prominent CTA pill above the list, header cluster (credits chip / bell / user chip). Change: sidebar bg = `paper`, not dark; active nav row = `accent-soft` fill + accent icon, no shadow (chrome, not a card). Tokens: CTA button gets `pop-sm` + pen; credit chip is a pill on `accent-tint`, count in mono; user chip uses `pen-2` hairline only. Mono: only the credit number.

**2. Create page (tv-23/24).** Keep: big Baloo 2 headline (regular + italic accent word), icon step-rail above the paste box, paste box with bottom toolbar, suggestion card, recent-results thumbnail row. Change: paste box = `card` + pen + `pop`; step-rail icons = Lucide, accent when active/selected, `pen-2` when idle; recent-thumbnail "NEW" ribbon becomes an accent badge with its own thin pen outline. Right drawer (tv-24): icon+title+helper+value rows are *not* individually outlined — they're rows inside one outlined panel; radio cards (Cách kể / Bố cục khung hình) each get `pop-sm`, selected = accent border + `accent-soft` fill, unselected = pen only, no shadow change.

**3. Config page (tv-25).** Keep: centered 9:16 preview, right panel of grouped icon-led rows, bottom tab strip of step-summary cards. Change: preview stays dark (the deliberate exception) but sits inside a pen+`pop` phone-bezel card so it reads as inset, not broken. Bottom tab strip = the "colored top edge card" pattern (see D below): each tab is a pen-outlined card with a 3px top strip — **accent for the active step, `pen-2`/neutral for the rest** (do not invent 6 hues; Desoul has one accent, so active/inactive is a fill-weight distinction, not a color-per-topic one). Title in Source Sans 3 medium, the 2-line summary values in mono.

**4. Card/config sub-step (tv-28).** Same shell. Sliders: track = `track` token, filled portion = accent, thumb = small pen-outlined circle; helper caption under each control in `muted` small Source Sans 3; the numeric value beside every slider (%, px) is mono. Selected bottom-tab gets the accent top-edge + `accent-soft` fill to show current position in the flow.

**5. Layers editor (tv-33).** Keep: left vertical icon toolbar, canvas with zoom controls, right stack list with drag handles. Change: canvas keeps the checkerboard/dark exception, framed in one pen+`pop` "stage" card; toolbar icons sit in one outlined strip, not individually shadowed; zoom controls = small pen-outlined pill cluster, bottom-right of canvas. Layer rows: plain rows, hover = faint tint, selected = `accent-soft` row + accent left-bar — not each row individually outlined (would look like a stack of separate cards, not a list). "Sao chép từ Hook" = ghost/outline button, not filled (it's a secondary action). Mono: `(3/20)` layer count, zoom `%`.

**6. Library grid (grouped by day).** Keep: asset-type tab row, search/sort/view toolbar, day-grouped thumbnail grid. Change: locked/empty state = lock icon + headline + helper + filled accent CTA, the whole panel pen+`pop` (copy tv-21's empty state exactly — it already does this right). Thumbnail cards = `pop-sm`, lift on hover. Day-section headers = small Baloo 2, not mono, not all-caps larger than 11px. Mono: file-size/count counters ("0 B / 50.0 MB · 0/30 tệp").

**7. Render/edit page (tv-12).** Keep: scene list + video player two-column split, per-scene icon actions, nested comment replies with like counts. Change: each scene = its own `pop-sm` card with a small `accent-soft` "CẢNH #n" chip; player stays dark, framed in the same pen-outlined bezel card as the config-page preview so the two dark surfaces in the product feel like one system, not two different bugs. Mono: like counts, scene numbers, timecodes.

**8. Product tour (tv-32).** Keep: dimmed backdrop, one spotlighted element, tooltip near it, "N/8" counter, skip/continue footer. Change: tooltip card is the one floating surface → pen + `pop`; backdrop is `ink` at ~55–65% opacity as a *transient scrim*, not a surface (same exception every light-mode modal system makes — the scrim isn't "dark mode," it's a temporary overlay). Counter in mono, title in Baloo 2, body in Source Sans 3, footer = ghost "Bỏ qua" + filled accent "Tiếp tục."

## C. Product tour: recommendation

**Build a ~50-line native implementation**, not a library. Reasons, with evidence:

- The classic `box-shadow: 0 0 0 9999px` spotlight trick breaks the moment the highlighted element sits inside a parent with `transform`/`filter`/`opacity` — which a card-heavy, pen+shadow UI will have everywhere. Driver.js's own maintainers rewrote away from box-shadow to an SVG cutout for exactly this reason. [usertourkit.com/blog/element-highlighting-techniques-box-shadow-svg-canvas](https://usertourkit.com/blog/element-highlighting-techniques-box-shadow-svg-canvas)
- The correct primitive is a full-viewport `<svg>` at `document.body` with one `<path>` using `fill-rule="evenodd"` (outer viewport rect minus an inset rounded-rect around the target's `getBoundingClientRect()`), ~30–40 lines, plus a positioned tooltip `<div>` styled with the brand's own pen+`pop` card — no CSS fighting a library's defaults. Reference implementation (adapt directly): [usertourkit.com/blog/element-highlighting-techniques-box-shadow-svg-canvas](https://usertourkit.com/blog/element-highlighting-techniques-box-shadow-svg-canvas)
- If a dependency is wanted anyway: **Driver.js** (MIT, ~5KB gzipped, vanilla JS, SVG-cutout by default, drive from a `"use client"` component's `useEffect`) is the only one worth it in an App Router project. Skip React Joyride (34–85KB, inline styles fight Tailwind/brand tokens) and Shepherd.js (AGPL-3.0 — avoid for a shipped product). [usertourkit.com/blog/react-tour-library-benchmark-2026](https://usertourkit.com/blog/react-tour-library-benchmark-2026)

Given the brand needs custom pen+shadow tooltip styling regardless, **native wins on the ladder** — a library buys nothing once you're not using its default UI.

## D. Icons + fonts

**Icons — keep Lucide** (`lucide-react`, already installed). ISC license, 1,778 icons, 24px grid / 2px stroke, shadcn/ui's own default. The "plain text" bug was never the icon *set*, it was that icons weren't used at all — fix that first. One tuning knob: bump `strokeWidth` from the 2px default to ~2.25–2.5 on nav/section icons so their weight matches the 2.5px pen line; thin icons next to a thick hand-drawn outline is its own version of "reads flat." If broader coverage is ever needed, **Tabler** is the only true drop-in (same 24px/2px grid, MIT, ~6,143 icons incl. filled variants) — skip Phosphor (different 256 grid, weight-per-icon decision overhead) and Iconoir (smaller, more editorial) unless a redesign specifically wants that hand-drawn-icon feel. [allsvgicons.com/compare/tabler-vs-lucide](https://allsvgicons.com/compare/tabler-vs-lucide/) · [svgicons.com/articles/lucide-vs-tabler-vs-phosphor-icons](https://svgicons.com/articles/lucide-vs-tabler-vs-phosphor-icons)

**Fonts, Vietnamese coverage:**
- **Baloo 2** — confirmed: Google's own specimen states the family "supports one Indic/Arabic script plus Latin, Latin Extended, and **Vietnamese**." Safe for every VI heading. [fonts.google.com/specimen/Baloo+2](https://fonts.google.com/specimen/Baloo+2)
- **Source Sans 3** — Fontsource lists `vietnamese` as an explicit subset. Safe for VI body/labels. [fontsource.org/fonts/source-sans-3](https://fontsource.org/fonts/source-sans-3)
- **Source Code Pro** — 2019 update explicitly added Vietnamese glyph coverage. Safe (and moot for most uses since mono is numbers/paths/ids, mostly ASCII anyway). [fontsource.org/fonts/source-code-pro/about](https://fontsource.org/fonts/source-code-pro/about)
- **Fredoka** — variable `wght 300–700`. Vietnamese coverage is **not clearly confirmed** (language lists found don't explicitly include it, unlike Baloo 2/Source Sans 3). **This is a non-issue under the existing brand rule**: Fredoka is scoped to the DESOUL wordmark and the all-caps English sub-word only, "never body copy" — it will never be asked to render a Vietnamese diacritic in this product. Don't extend its use beyond the logo lockup.
